== filter md ## The Format ### Sections Neodocs are made of sections. Each one starts with two dashes and a name. Content for the section follows below it. == filter highlight("neo", class="code-block") -- title A Neodoc Overview == endfilter The section names can be pretty much anything as long as they don't contain spaces. ### Section Flags and Attributes Sections can have metadata attached to them in the form of __flags__ and __attributes__. Flags are pieces of text that start with two dashes on the lines below a section name. For example, this is an __image__ section with a flag for the image's filename (the content portion of the section is used for the image's alt text). == filter highlight("neo", class="code-block") -- image -- example-image.jpg The word "example" written in white text on a dark read background. == endfilter Attributes work the same as flags but start with a keyword followed by a colon. For example, here's a "aside" section with a "class" attribute of "warning": == filter highlight("neo", class="code-block") -- aside -- class: warning There is where you can put something that needs extra attention. == endfilter ### Section Types The content of each section is treated as paragraphs by default. This can be changed by adding a **section type** after the name. The **list** type is an example: == filter highlight("neo", class="code-block") -- notes list - A note about something. - Another note about something else. == endfilter Another type is **checklist**: == filter highlight("neo", class="code-block") -- todo checklist [] Something that needs to be done [x] Something that has been done. == endfilter == endfilter
Check this out for more info on Section Types == filter md The full list of section types is: - checklist - a collection of items with a status associated with them. - csv - a collection of CSV data. - json - a JSON object. - list - a list that uses bullets for each item. - numbered - a list that uses numbers for each item. - p - paragraph based content. - raw - a raw block of text with no addition processing. Using a section type for the name of a section works too. For example, creating a generic numbered list is done with: == filter highlight("neo", class="code-block") -- numbered 1. A note about something. 2. Another note about something else. == endfilter There are also a few section names that are processed as __raw__ instead of paragraphs by default. They are: - css - html - script - math - pre - svg - template - textarea == endfilter
== filter md ### Spans Section content can contain spans. They're snippets that wrap text to alter it in some way. A basic span looks like this: == filter highlight("neo", class="code-block") <> == endfilter The parts are: - A pair of less than signs (`<<`) that mark the start of the span. - The type of span (e.g. `code` in the example above). - A pipe (`|`) character that separates the span type from the span's content. - The span's content itself. - A pair of greter than signs (`>>`) that mark the end of the span. Here's what a span looks like surrounded by more content: == filter highlight("neo", class="code-block") The JavaScript function <> prints information to the developer console. == endfilter When that content is turned into a web page the span turns into an HTML `<code>` tag like this: == filter highlight("html", class="code-block") The JavaScript function console.log() prints information to the developer console. == endfilter ### Span Attributes Spans can have attributes that further enhance their content. They're added by using additional pipes to separate them from the content. For example, a class attribute can be added to the span like this: == filter highlight("neo", class="code-block") <> == endfilter which outputs this HTML: == filter highlight("html", class="code-block") console.log() == endfilter Multiple attributes can be added by using more pipes. For example, this span (which also shows how spans can be split across lines) adds a `data-language` attribute that can be used to apply syntax highlighting to the code: == filter highlight("neo", class="code-block") <> == endfilter The output HTML looks like this: == filter highlight("html", class="code-block") console.log() == endfilter ### Span Shorthands There are shorthands for frequenly used span types. For example, backtics denote code spans. The orignal example from above: == filter highlight("neo", class="code-block") <> == endfilter can also be written as: == filter highlight("neo", class="code-block") ``console.log() |class: featured |language: javascript`` == endfilter
Here's some more info on Span Shorthands The beta testing list of span shorthands is: - \`\`TEXT\`\` - code span - \*\*TEXT\*\* - bold span - \_\_TEXT\_\_ - emphasis span - \~\~TEXT\~\~ - strikethrough span - ^^TEXT^^ - footnote - \>\>TEXT|URL>> - link - [[FILEPATH|alt: ALT_TEXT]] - image span
