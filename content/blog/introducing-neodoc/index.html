I'm Alan. I'd like to introduce you to NeoDoc. A writing format for the Atmosphere^^1^^. -- comment You're seeing the raw format of this post right now. That's because the NeoDoc parser hasn't been integrated into the site yet. That's no problem. NeoDoc was designed to make creating content easy. A big part of that was ensuring it's easy to read too. The format is like >>Markdown| https://www.markdownguide.org/>>. But, you can do way more with it. For example, when NeoDoc files are transformed into web pages the ``-- comment`` sections are hidden. So, this note will automatically disappear when the parser is in place. Appropriate, since at that point you'll no longer be seeing the raw text. Check out >>the home page|/>> for some more examples. -- h2 How It Started Three years ago, I hit my breaking point with website tools. I was using Next.js^^2^^ and tried to correct a typo on my site. I changed a single character and everything broke. Some part of the process that built the site simply stopped working. My site is 25 years old. I have no desire to deal with that shit for the next 25. So, I started building my own tools. Since I had a blank slate, I re-examined every aspect, including the use of Markdown for content. -- h2 From Scratch One of my favorite phrases is: -- blockquote/ Broken gets fixed. Shoddy is forever. -- /blockquote As great as Markdown is for simple blog posts, it sucks at making interesting pages. Anything beyond basic formatting and you have to roll your own HTML. For the longest time, I considered it a shoddy experience. As I thought about making content for the rest of my life, I realized it's broken. Or, at least, it's the wrong tool for the job. When you can't do interesting things in HTML without having to actually write the HTML, it's not up to snuff. The realization started me down the path of designing a new content format. Something as easy to use as Markdown without sacrificing the power of the web's native language. Three years later, NeoDoc is the result. -- h2 Where It's At The NeoDoc parser is currently embedded in my static site generator. Extracting it has been on the todo list forever. It just wasn't a priority. Folks would have to make new tools to use it. Not likely, given the quality of the established website building options. You know what doesn't have established options yet? **The Atmosphere**. It's the Wild West. Harkening back to the early days of the web. Before everything was jammed into the conformity of corporate, siloed social networks. It's awesome. -- h2 Taking A Swing We're at an epoch. Standards haven't been set. Once they have, they'll be insurmountable. Thanks to AT Proto, we don't have to worry about siloed content. We can move what we make at our own volition. But, if we're not careful, we'll end up with Markdown again. Or, worse. We'll end up with no standard at all. The promise of the freedom of movement will be lost to a cacophony of content formats. Apps unintentionally locking us in because no one else is set up process content the way they store it. And so, I'm offering NeoDoc as a path forward. Not just for websites, but as a portable format to underlie the Atmosphere. A human readable way to ensure we can make the stuff we make go where we want. If that sounds like the kinda thing you're into, you can follow along >>on this site|/>> or >>on Bluesky |https://bsky.app/profile/neodoc.style>>. Until next time, I'll see you in the Atmosphere. ->>a| https://bsky.app/profile/alanwsmith.com>> -- endnote I'm not the only one thinking about making it easier for different apps to use the same content. I've got >>an entire manifesto| https://www.alanwsmith.com/en/2v/xa/cn/vj/>> banging ideas around. Lots of it is pondering how to use RSS to make connections. The good news is that with the protocol set we can work on interoperability of the content. I'd love to see NeoDoc fill that roll. More important is that __something__ fills it. To be truly decentralized we can't accept vendor lock-in of our content. -- endnote NeoDoc is the spec for the plain-text file format. There's more to the idea than that. Basically, the project is to create an AT Proto lexicon centered around the format that includes a default set of templates for how to process specific sections and a way to send CSS payloads to style them. Every app that renders HTML with the defaults will produce the same output. For example: -- code/ -- neodoc -- h2 Hello, World! Welcome to the Atmosphere. -- /code will render like this by default: -- code/ -- html <section class="neo-h2"> <h2>Hello, World!</h2> <p>Welcome to the Atmosphere.</p> </section> -- /code Individual accounts can provide a default set of styles for there posts as well as overrides for individual posts. Apps will have a default set of styles that they can use if no user supplied style exists or if they decide to override it. -- endnote The NeoDoc format includes templating tokens designed to be used with >>MiniJinja| https://docs.rs/minijinja/latest/minijinja/>> (The Rust version of >>Python's Jinja template engine| https://jinja.palletsprojects.com/en/stable/>>). The NeoDoc.style spec includes details on how templating is handled. (The reference implementation will include template rendering out of the box.) There's a bunch more detail there that will come in future posts and as the docs get built out. The key takeaway is that NeoDoc ships with a default set of templates for a selection of section types (e.g. ``-- title``, ``-- h1``, ``-- blockquote``) but anyone can define their own section types and provided the templates to render them. -- endnote I haven't mentioned moderation yet. -- endnote A final thing to mention in this post is the idea of using NeoDoc content as a free from database. For example, if you have ``-- book-review`` sections spread across your files they can be aggregated into a single page. If a bunch of folks use the same section setup, the can be collected across accounts. You can make the next Good Reads simply by watching the firehose for specific sections. They won't all have the same format. That's a feature. Not a bug. We've lived so long in a world where our content has been defined by database schemes we've forgotten what it's like for things to have a personal touch. NeoDoc brings that back. -- footnote -- id: 1 Well. NeoDoc was originally designed for my static site generator. But, damned if it's not perfect the Atmosphere. -- footnote -- id: 2 Look.
