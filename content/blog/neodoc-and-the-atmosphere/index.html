The more I learn about it, the more it has my attention. I don't remember the last time I was this excited about new tech. My introduction was standard.site^^standard^^. It made several appearances in my feed over the past few weeks. I jumped on it^^jump^^. It's the kind of stuff I dream about^^manifesto^^. I wasn't entirely sure how content worked with it and looked around for details. One thing the leaflet^^leaflet^^ post I found points out is that the lexicon is for content discovery and social features, but -- blockquote/ Importantly, [it] is not a standard for site content. -- /blockquote The only other^^other^^ post I've seen on a content standard for the Atmosphere has to do with a wordpress lexicon for publishing HTML. I submit that HTML could work as a standardized content format. It's a battle tested standard that renders natively in browsers without modification. There are, however, a couple things that recommend against it. -- numbered/ 1. It's not friendly to write by hand. Unless you're hard-core, it's not something most folks are into. 2. It's tough to standardize HTML content types. Microformats^^micro^^ were an attempt. They never took off. That's at least in part because they lock the content into the rendering layer. You can do all kinds of things with CSS, but your locked into a specific set of elements and have to set up a parser if you want to use the data independently. -- /numbered Markdown^^md^^ is another option. It's easy to learn. It also has huge market share in the developer community. It's great for blog posts, but sucks for anything beyond that. You can always roll your own HTML to do interesting stuff. But, your back to its unwieldy nature and parsing complexity at that point. Markdown also lacks the ability to add metadata to content. For example, say you want to apply a custom style to an ``H2`` element on a page. There's no mechanism to do that in native Markdown. You have to switch to inline HTML. -- h2 Introducing NeoDoc There are other content formats out there. I reviewed a bunch when I got fed up with Markdown and decided to switch to something else for >> my sites | https://links.alanwsmith.com/ >>. None offered the combination of flexibility and ease of use I was after. So, I designed a new format. It's called NeoDoc and you're reading it right now^^maybe^^. The format is designed to be as simple as possible without sacrificing horsepower. It breaks down like this: -- list/ -- class: example - NeoDocs are build from sections. Each one starts with two dashes and a name. For example, we're current in a ``-- list`` section. (The trailing ``/`` lets other sections nest inside the list which we want for the ``code`` section below.) - Sections can have attributes like the ``-- class: example`` above. They can be used as basic metadata about the section or added as attributes to the HTML output. - There's a pre-defined set of sections like: ``-- list``, ``-- checklist``, and ``-- numbered``. You can also make ad hoc sections simply by naming them. For example, you can make a ``-- book-review`` section to collect and format your book reviews. - Inline formatting and shorthands are available for spans of text. For example, you can wrap text in asterisks which convert to HTML ``strong`` tags. -- code/ **Alfa Bravo Charlie** -- /code - Inline spans can also have attributes. For example, here's a ``class`` attribute with the shorthand: -- code/ **Alfa Bravo Charlie | class: red** -- /code -- /list That's pretty much it. The rest of it comes down to processing. Details on that and how the everything works are on the >> NeoDoc site | https://neodoc.style/ >>. -- h2 The Offering I started working on NeoDoc three years ago. It's currently embedded in my personal static site generator. It powers the >> three thousand or so pages I've posted there | https://www.alanwsmith.com/neo-files/report >>. The format feels like a natural fit for the Atmosphere. So, I'm extracting the NeoDoc tools to make them independently available. Once they're ready, I'll make them open source so anyone can use them. -- h2 Outro I'm incredibly excited about the Atmosphere. I hope NeoDoc can become a part of it. Because, if I'm right, the ability to easily move the stuff we make to wherever we want will be key to practical decentralization. I believe NeoDoc can be instrumental in making that happen. If you've got questions or feedback, I'm all ears: >> @al9000.com | https://bsky.app/profile/al9000.com >> -alan -- endnote I'd love to see NeoDoc become an active participant in the Atmosphere. However, it's way more important to me that content gets standardized on __something__, regardless of what it is. There will always be a need for custom formats for specific applications. For everything else, if we can't move it, it fails the promise and potential of decentralization. -- endnote/ The reference NeoDoc app (when it's extracted from my static site generator) performs three functions: -- numbered/ 1. Takes a NeoDoc formatted input and transforms it into a JSON formatted AST. 2. Transforms a NeoDoc AST into HTML based on a standardized set of default templates. 3. Accepts optional templates that override the defaults when generating output. -- /numbered More details on how all that works will be in the docs. -- /endnote -- endnote Another thing Markdown suffers from is lack of an official standard. Lots of different, competing standars have cropped up as a result. NeoDoc's development includes a standard in the form of a comprehensive test suite for use in validating complicance with format parsing and outputs. -- endnote NeoDoc isn't a theoretical idea.
